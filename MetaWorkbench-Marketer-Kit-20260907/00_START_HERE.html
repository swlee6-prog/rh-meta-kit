Rabbit Hole 소재 작업대 · 마케터 올인원 안내

2026년 9월 7일 전달본

이 안내와 같은 폴더의 파일만 받으면 시작할 수 있습니다. ZIP을 모두 압축 해제한 뒤 00_START_HERE.html을 더블클릭하세요. 이 문서는 인터넷 없이도 열리며, 작업대 로그인·광고 조회·업로드에는 인터넷이 필요합니다.

작업대: meta-ads.rabbithole-studios.io
운영 문의: 강승민 · smkang@cookapps.com

이 도구로 하는 일

검수한 9:16·1:1·16:9 MP4를 올려 참조 광고의 문구·제목·CTA·목적지·배치를 유지한 새 PAUSED 광고를 만듭니다. 대상은 Rabbit Hole 광고계정입니다. 최종 활성화와 집행 결정은 Ads Manager에서 담당자가 합니다.

이미지·playable·다른 게임과 Google Sheet 기반 월수금 정기 실행은 아직 지원하지 않습니다. 이 묶음은 Windows의 Claude Code가 로컬 파일을 읽어 CLI로 작업하는 방식입니다. 일반 Claude 웹 채팅이나 클라우드 예약 루틴에 ZIP을 첨부하는 것만으로 실행되지는 않습니다. Claude Code를 사용하지 않으면 아래 브라우저 사용법대로 작업할 수 있습니다.

가장 빠른 시작

  1. ZIP을 모두 압축 해제합니다. ZIP 안에서 실행하지 마세요. 실행기와 CLI는 같은 폴더에 둡니다.
  2. 아래 ‘처음 한 번’ 순서로 Node.js와 작업대 로그인을 준비합니다. 이미 연결했다면 doctor로 상태만 확인합니다.
  3. 압축을 푼 폴더에서 Claude Code를 열고 CLAUDE_PROMPT_KO.txt의 대괄호를 채운 문구를 전달합니다. 영상 폴더는 별도로 지정해도 됩니다.
  4. Claude가 반환한 새 광고 번호와 작업 증빙을 확인하고 Ads Manager에서 최종 검수합니다.

파일 용도
00_START_HERE.html / 00_START_HERE.md 이 올인원 안내. HTML은 브라우저로 열거나 인쇄할 수 있습니다.
CLAUDE_PROMPT_KO.txt 마케터가 조건을 채워 Claude에게 전달할 문구

원본 영상과 로그인 토큰은 포함하지 않았습니다. 예시의 ID·검수 해시는 실제 값으로 바꿔야 하며, manifest는 Claude에게 작성하도록 맡겨도 됩니다. 이 파일 묶음은 프로그램 전체를 재배포하는 개발자 소스가 아니므로 npm install이나 Cloudflare 로그인은 필요하지 않습니다.

처음 한 번

  1. start-windows.cmd를 더블클릭합니다. 기본으로 연결 진단(doctor)을 실행하고 결과를 보여줍니다. Node.js가 없거나 22 미만이면 https://nodejs.org/en/download에서 22 이상을 직접 설치하고 터미널을 다시 여세요. 실행기는 자동 설치, 관리자 권한 요청, ExecutionPolicy 변경을 하지 않습니다.
  2. 작업대의 Claude Code 연결에서 본인 7일 토큰을 발급합니다. 이 폴더에서 사람이 직접 PowerShell을 열어 다음을 실행합니다.
.\start-windows.cmd login
.\start-windows.cmd doctor
.\start-windows.cmd whoami

login의 숨김 입력에만 토큰을 붙여넣습니다. doctor의 "ok": true로 연결 상태를 확인하고, whoami로 본인 이메일을 확인합니다. Claude에게 토큰이나 저장 파일을 넘기지 마세요. 토큰은 7일 뒤 만료되므로 그때 새로 발급해 다시 로그인합니다.

  1. 아래 문구의 대괄호를 실제 값으로 바꾸고 Claude에게 전달합니다. 소재 폴더에는 검수한 9:16·1:1·16:9 MP4를 하나씩 둡니다. 각 파일은 512 MiB 이하여야 합니다. 아직 검수하지 않은 항목을 검수했다고 적지 마세요.

Claude에게 전달할 문구

이 폴더의 CLAUDE.md와 START_HERE_KO.md를 읽고 Rabbit Hole 소재 작업을 완료해 주세요.
소재 폴더: [예: C:\광고 소재\이번 주 영상]
대상 광고 세트: [ID 또는 정확한 이름]
검수한 참조 광고: [ID 또는 정확한 이름]
신규 광고명: [기존 광고와 구분되는 이름]
언어: [예: EN]
검수 범위: 이 폴더의 9:16·1:1·16:9 영상 내용과 참조 광고의 문구·CTA·목적지·배치를 확인했습니다.
승인 범위: 위 설정을 유지하고 이 소재 묶음으로 새 creative와 새 PAUSED 광고 1개를 생성하는 데 승인합니다.

doctor → 대상/참조 조회와 preview → manifest 작성 → check-manifest → prepare 또는 기존 초안 resume → 승인된 submit 1회 → wait → lineage → 증빙 export까지 진행하세요.
이미 명시한 대상·참조·생성 승인에 대해 다시 묻지 마세요. 정보 누락, 후보가 모호한 경우, 검수본 변경이 있을 때만 필요한 내용을 묶어 질문하세요.
토큰 원문이나 credential 파일을 읽지 말고 저장된 로그인을 CLI가 사용하게 하세요. 최초/만료 로그인은 제가 직접 숨김 입력으로 합니다.
기존 광고 변경·활성화·예산 변경은 금지합니다. 응답이 불명확하면 재제출하거나 새 초안을 만들지 말고 같은 작업의 상태를 확인하세요.
본인이 만든 작업이 FAILED_TERMINAL + AD_PAUSED_TIMEOUT이고 확정 광고·creative·최초 이력이 있으면 recheck-paused OPERATION_UUID를 1회 실행하세요. 계속 심사 중이거나 검증 실패이면 같은 작업의 status와 export로 증빙을 남기고 멈추세요. 생성 결과 불명확·기록 누락·다른 오류·다른 사람의 작업은 관리자에게 전달하세요.
재확인 성공 응답 뒤에도 status로 AWAITING_MARKETER_REVIEW 상태를 확인한 후 lineage와 export를 마치세요.
작업 ID·새 광고 ID·실제 최종 상태·증빙 경로와 남은 확인 사항을 알려주세요.

생성까지 승인하지 않으려면 승인 범위를 “검수와 초안 업로드까지만 진행하고 submit은 하지 마세요”로 바꿉니다. 아직 모르는 ID는 정확한 이름을 적어도 되지만 같은 이름이 여러 개면 Claude가 구분을 요청합니다. 영상이 여러 묶음이면 각 묶음의 이름과 생성 수를 구체적으로 지정하세요. 추가 묶음을 임의로 생성하지 않습니다.

파일과 진단 결과

PowerShell에서 경로의 공백·한글을 보존하려면 따옴표를 사용하세요. 아래 명령의 상대 경로는 현재 PowerShell 폴더 기준이며, manifest 안의 상대 영상 경로는 manifest 폴더 기준입니다.

.\start-windows.cmd check-manifest "C:\광고 소재\이번 주 영상\manifest.json"
.\start-windows.cmd --help

check-manifest는 로그인 없이 로컬 JSON/BOM, 파일·MP4 헤더·크기·SHA-256을 검사합니다. 화면비 항목 세 개가 있다는 것과 실제 영상 해상도가 맞다는 것은 다릅니다. 해상도·회전·재생·게임/내용·Meta 호환성·참조 변경은 별도 확인이 필요하며 결과의 notChecked를 읽으세요. 검사만으로 업로드나 광고 생성은 일어나지 않습니다.

진단/상황 할 일
Node.js 없음 / 22 미만 공식 사이트에서 설치한 뒤 터미널을 다시 엽니다.
login 필요 / unauthorized 본인 7일 토큰을 발급해 직접 login합니다. 만료·취소·오입력 여부는 이 응답만으로 구분되지 않습니다.
unsafe_permissions 로컬 NTFS 사용자 프로필을 쓰고 관리자에게 문의합니다. 권한 검사를 우회하지 않습니다.
access_redirect / access_html 운영자에게 API 전용 경로 설정을 확인해 달라고 합니다. 웹 인증을 해제하지 않습니다.
네트워크·서비스 오류 / rate_limited 결과의 nextAction을 확인합니다. 준비·제출을 반복하지 않습니다.

doctor와 check-manifest는 정상일 때 종료 코드 0, 조치가 필요하면 1을 반환합니다. Claude는 더블클릭용 대기 없이 .\start-windows.cmd doctor처럼 명령을 명시해서 실행합니다.

중단된 작업을 이어갈 때

prepare가 출력한 작업 ID를 보관하세요. 업로드 중 끊겨도 prepare를 다시 실행하지 않습니다.

.\start-windows.cmd status OPERATION_UUID
.\start-windows.cmd resume OPERATION_UUID --manifest ".\manifest.json"

ID가 없으면 list --query "신규 광고명"으로 기존 초안을 먼저 찾습니다. 같은 원본·설정의 미제출 초안만 재개할 수 있습니다. 이미 제출했거나 생성 결과가 불명확하면 관리자에게 작업 ID와 증빙을 전달합니다.

광고 생성 후 상태 확인이 늦어질 때

본인이 초안을 만든 작업(submitted_by)이 FAILED_TERMINAL이고 오류가 AD_PAUSED_TIMEOUT이면 다음을 한 번 실행합니다. 확정된 광고·creative와 최초 이력 기록이 있는 작업만 가능합니다.

.\start-windows.cmd recheck-paused OPERATION_UUID

이 명령은 기존 광고와 참조·검수 hash·최초 이력·PAUSED 상태·미리보기를 모두 다시 검증합니다. Meta에는 조회만 하며, 모두 통과하면 기존 작업 상태를 갱신합니다. 새 광고 생성이나 기존 광고 수정은 하지 않습니다.

성공 응답 뒤에도 status로 AWAITING_MARKETER_REVIEW 상태를 확인하고 lineage와 export를 마칩니다.

계속 AD_PAUSED_PENDING 등으로 심사 중이거나 검증을 통과하지 못하면 재확인을 반복하지 말고 같은 작업의 status와 export로 증빙을 남긴 뒤 관리자에게 전달합니다. prepare·submit을 다시 실행하지 마세요. 생성 결과 불명확, 확정 ID·최초 이력 누락, 다른 오류, 다른 사람의 작업은 기존 Owner 안전 재확인 대상입니다. 이 owner 기능은 CLI가 실행할 수 없습니다.

AWAITING_MARKETER_REVIEW는 작업대 검증 완료이며 Meta 심사 승인이나 집행 시작을 뜻하지 않습니다. 재확인도 심사 완료를 강제하지 못합니다. 최종 집행은 마케터가 Ads Manager에서 검수한 뒤 결정합니다.

브라우저에서 새 광고 준비

1. 광고 세트와 참조 광고 검수

  1. 새 광고 준비를 엽니다.
  2. 대상 광고 세트를 선택하고, 그 세트의 참조 광고를 선택합니다. 목록이 길면 더 불러오기를 사용합니다. 목록 조회가 실패하면 목록 다시 불러오기를 누릅니다.
  3. 정확한 ID를 알고 있다면 광고 ID로 직접 선택을 펼쳐 입력할 수 있습니다. 직접 입력해도 계정·광고 세트 검증은 동일하게 적용됩니다.
  4. 참조 광고 확인을 누릅니다. 광고명, 캠페인, 광고 세트, 본문, 제목, CTA와 목적지를 읽고 **문구·CTA·목적지를 확인했습니다.**에 체크합니다.

참조 광고 선택이나 ID를 바꾸면 다시 검수해야 합니다. 검수한 뒤 참조 광고의 이름·소재·문구 등이 바뀌면 서버가 생성을 중단합니다. 변경 내용을 확인하고 최신 검수본으로 새 작업을 준비하세요.

2. 세 영상 업로드

  1. 기존 광고와 구분되는 신규 광고명과 언어를 입력합니다. 광고명은 160자 이하이며 문자·숫자·공백과 _ . ( ) -를 사용할 수 있습니다.
  2. 세 화면비에 맞는 MP4를 선택합니다. 각 영상의 재생, 해상도, 길이와 내용을 확인합니다.
  3. 업로드하고 검수하기를 누릅니다. 파일 해시 계산과 업로드가 끝날 때까지 창을 유지합니다.
  4. 업로드가 끝나면 상세가 열리고 상태가 제출 준비가 됩니다. 이 단계에서는 Meta 광고를 아직 생성하지 않습니다.

3. 신규 PAUSED 생성 확인

  1. 상세 화면에서 업로드된 세 영상을 다시 확인합니다. 필요하면 영상 다운로드로 원본을 받습니다.
  2. **세 영상을 확인했습니다. 기존 광고를 변경하지 않고 새 PAUSED 광고를 생성합니다.**에 체크합니다.
  3. 새 PAUSED 광고 생성을 한 번 누릅니다.
  4. 제출이 확인되면 서버가 처리를 계속하므로 브라우저를 닫아도 됩니다. 작업 이력 또는 작업 상태 새로고침으로 결과를 확인합니다.

생성 버튼을 누른 뒤 연결이 끊기면 먼저 같은 작업의 상태를 확인하세요. 응답이 없다고 같은 작업을 반복 제출하거나 새 작업으로 다시 생성하지 않습니다.

작업 이력과 증빙

작업 이력에서 광고명, 작업 번호 또는 신규 광고 번호로 검색하고 상태로 좁힐 수 있습니다. 이전 작업 더 보기로 이전 이력을 불러옵니다. 이력과 열린 상세의 진행 상태는 화면이 활성화되어 있고 업로드 중이 아닐 때 약 15초마다 갱신됩니다.

광고명을 눌러 상세를 열면 작업 번호, rh-op:<작업 번호> 검색 태그, 참조 광고, 신규 광고·creative 번호, 세 영상과 작업 기록을 볼 수 있습니다. 작업 증빙 다운로드는 설정, 검수본, 소재 정보, 감사 기록과 외부 생성 요청 기록을 JSON으로 내보냅니다. 검색 태그 복사는 Ads Manager에서 생성된 리소스를 찾을 때 사용합니다.

화면 상태 의미와 다음 행동
업로드 대기 초안이 있거나 일부 영상 업로드가 남았습니다. 같은 작업에서 업로드를 이어갑니다.
제출 준비 세 영상 업로드가 완료됐습니다. 상세에서 검수하고 명시적으로 신규 PAUSED 생성을 제출합니다.
제출됨 / CDN 검증 중 / Meta 영상 처리 중 / 광고 생성 중 서버가 처리 중입니다. 상태를 확인하며 기다립니다.
마케터 검수 대기 작업대가 새 광고의 PAUSED 상태와 필요한 검증을 확인했습니다. Ads Manager에서 최종 검수합니다. Meta 심사 승인이나 광고 집행 완료를 뜻하지 않습니다.
안전 중단 검증에 실패했습니다. 중단 전에 영상·creative·광고가 이미 생성됐을 수 있습니다. 상세 오류와 작업 번호를 관리자에게 전달합니다.
생성 여부 확인 필요 Meta 생성 요청의 결과를 확정하지 못했습니다. 자동 재시도하지 않습니다. 같은 작업 상태와 검색 태그를 확인하고 관리자에게 넘깁니다.

광고 번호가 비어 있어도 미생성이 확정된 것은 아닙니다. 관리자는 작업 원장과 Meta의 실제 상태를 함께 확인해야 합니다. Owner 안전 재확인은 owner 브라우저에만 표시되며, 기존 광고를 수정하거나 생성 POST를 다시 보내는 기능이 아닙니다. 확인에 필요한 기록이 부족하면 복구를 중단합니다.

AD_PAUSED_TIMEOUT은 새 광고가 생성됐지만 Meta의 최종 PAUSED 상태 확인이 제한 시간 안에 끝나지 않았다는 뜻입니다. 광고 설정이 PAUSED여도 Meta 심사가 진행 중이면 발생할 수 있습니다. 본인이 만든 작업이고 확정 광고·creative·최초 이력이 있으면 CLI의 recheck-paused로 한 번 재확인할 수 있습니다. 조건에 맞지 않거나 계속 심사 중이면 증빙을 남기고 관리자에게 전달합니다. 같은 작업을 새로 제출하지 않습니다.

업로드 중단·로그인 만료 복구

  1. 로그인 만료 안내가 나오면 다시 로그인합니다.
  2. 작업 이력에서 중단된 업로드 대기 작업을 열고 업로드 이어가기를 누릅니다.
  3. 안내된 원본 파일 세 개를 다시 선택합니다. 파일명·크기·SHA-256과 광고 설정·검수 해시가 기존 작업과 같아야 합니다.
  4. 참조 광고를 다시 확인하고 업로드를 이어갑니다. 완료된 파일은 다시 보내지 않으며, 확인된 업로드 조각은 같은 작업의 기록을 사용합니다.

파일을 다시 인코딩하거나 이름을 바꾼 경우 기존 작업을 이어갈 수 없습니다. 새 작업으로 전환을 사용하되 기존 작업이 이미 제출됐거나 생성 결과가 불명확한 경우에는 먼저 관리자에게 확인합니다. 참조 검수본이 바뀌었거나 임시 파일 보관 기간이 끝난 작업도 재개할 수 없습니다.

이미 제출 준비라면 파일을 다시 올리지 말고 상세에서 검수합니다. 안전 중단이나 생성 여부 확인 필요는 업로드 재개 대상이 아닙니다.

Ads Manager 최종 검수와 소재 이력

마케터 검수 대기 작업의 Ads Manager에서 검수를 열어 다음을 확인합니다.

  • 광고 번호와 creative 번호가 참조 광고의 번호와 다릅니다.
  • 광고가 PAUSED이며 올바른 광고 세트에 있습니다.
  • Feed, Story, Reels에 맞는 영상과 배치가 연결되어 있습니다.
  • 본문·제목·CTA·앱 목적지가 검수한 참조 설정과 같습니다.
  • Meta의 경고와 이슈를 확인했습니다.

활성화, 예산 결정과 기존 광고 중지는 담당자의 기존 Ads Manager 승인 절차로 수행합니다. 기존 광고의 이름이나 소재를 새 소재로 바꾸지 않습니다.

상세의 소재 이력 확인은 버튼을 누른 시점의 광고명·creative를 최초 생성 기록과 비교합니다. 변경이 감지되면 같은 광고 번호의 성과를 새 소재 성과로 단정하지 말고 관리자에게 변경 이력을 확인합니다. 상시 감시나 외부 Ads Manager 수정 차단 기능은 아닙니다.

이전 버전 작업에는 검수본이나 최초 생성 기준이 없을 수 있습니다. 이 경우 기준 없음 / untracked로 표시하며 현재 값을 과거 기준으로 만들어 넣지 않습니다.

보관과 이용 한도

미제출 임시 업로드는 생성 후 2일이 지나면 정리 대상입니다. 성공한 작업의 임시 파일은 처리 후 정리하며, 그 외 제출된 작업의 임시 파일은 마지막 변경 후 7일이 지나면 정리 대상입니다. 정기 정리 시점에 따라 실제 삭제 시각은 달라질 수 있습니다.

Meta가 사용할 공개 /meta/ 소재는 자동 삭제하지 않습니다. 공개 광고 영상은 비밀 저장소에 보관되는 파일이 아닙니다. 기존 공개 경로를 직접 덮어쓰거나 삭제하지 마세요.

사용자별 업로드 한도는 24시간 동안 20개 작업·5 GiB입니다. 이 한도는 Cloudflare 계정 전체의 청구 상한이 아닙니다. 작업대 권한이나 운영 Meta 토큰의 최소 권한 전환은 운영자가 관리합니다.
