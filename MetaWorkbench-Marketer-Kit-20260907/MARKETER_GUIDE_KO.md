# Rabbit Hole 소재 작업대 — 마케터 가이드

작업대: <https://meta-ads.rabbithole-studios.io/>

새 영상은 **새 creative와 새 광고 번호로 생성하고, 광고는 PAUSED로 준비합니다.** 기존 광고의 이름·소재·예산을 바꾸거나 광고를 활성화하는 기능은 제공하지 않습니다. 같은 광고 번호에 새 소재를 덮어쓰면 과거 성과와 새 소재 성과가 섞일 수 있습니다.

이 문서는 새 작업대 화면과 CLI의 사용법입니다. 이 문서의 메뉴가 없거나 CLI가 로그인 페이지를 반환하면 운영자에게 배포·경로 설정 상태를 확인합니다.

## 시작 전 확인

- 허용된 Google 계정으로 로그인합니다. 현재 구성에 등록된 주소는 `smkang@cookapps.com`, `support@rabbithole-studios.io`, `swlee6@cookapps.com`입니다.
- 대상은 Rabbit Hole 광고계정 `2810899719287325`입니다. 이미지·playable·다른 게임은 이 흐름에서 지원하지 않습니다.
- 9:16, 1:1, 16:9 MP4를 하나씩 준비합니다. 파일당 최대 512 MiB이며, 브라우저에서 영상과 화면비를 확인할 수 있어야 합니다.
- 같은 광고 세트의 참조 광고를 준비합니다. 세 화면비 영상을 가진 호환되는 Dynamic Creative여야 합니다. 목록에 보인다는 이유만으로 복제할 수 있는 것은 아닙니다.
- 참조 광고에서 문구·제목·CTA·앱 목적지·배치 설정을 이어받습니다. 다른 설정이 필요한 경우 맞는 참조 광고를 선택하세요.

마케터에게 Meta 원본 토큰, R2 API 키, Cloudflare 관리 권한은 필요하지 않습니다. 작업 이력은 허용된 사용자끼리 공유됩니다.

## 브라우저에서 새 광고 준비

### 1. 광고 세트와 참조 광고 검수

1. **새 광고 준비**를 엽니다.
2. **대상 광고 세트**를 선택하고, 그 세트의 **참조 광고**를 선택합니다. 목록이 길면 더 불러오기를 사용합니다. 목록 조회가 실패하면 **목록 다시 불러오기**를 누릅니다.
3. 정확한 ID를 알고 있다면 **광고 ID로 직접 선택**을 펼쳐 입력할 수 있습니다. 직접 입력해도 계정·광고 세트 검증은 동일하게 적용됩니다.
4. **참조 광고 확인**을 누릅니다. 광고명, 캠페인, 광고 세트, 본문, 제목, CTA와 목적지를 읽고 **문구·CTA·목적지를 확인했습니다.**에 체크합니다.

참조 광고 선택이나 ID를 바꾸면 다시 검수해야 합니다. 검수한 뒤 참조 광고의 이름·소재·문구 등이 바뀌면 서버가 생성을 중단합니다. 변경 내용을 확인하고 최신 검수본으로 새 작업을 준비하세요.

### 2. 세 영상 업로드

1. 기존 광고와 구분되는 **신규 광고명**과 **언어**를 입력합니다. 광고명은 160자 이하이며 문자·숫자·공백과 `_ . ( ) -`를 사용할 수 있습니다.
2. 세 화면비에 맞는 MP4를 선택합니다. 각 영상의 재생, 해상도, 길이와 내용을 확인합니다.
3. **업로드하고 검수하기**를 누릅니다. 파일 해시 계산과 업로드가 끝날 때까지 창을 유지합니다.
4. 업로드가 끝나면 상세가 열리고 상태가 **제출 준비**가 됩니다. **이 단계에서는 Meta 광고를 아직 생성하지 않습니다.**

### 3. 신규 PAUSED 생성 확인

1. 상세 화면에서 업로드된 세 영상을 다시 확인합니다. 필요하면 **영상 다운로드**로 원본을 받습니다.
2. **세 영상을 확인했습니다. 기존 광고를 변경하지 않고 새 PAUSED 광고를 생성합니다.**에 체크합니다.
3. **새 PAUSED 광고 생성**을 한 번 누릅니다.
4. 제출이 확인되면 서버가 처리를 계속하므로 브라우저를 닫아도 됩니다. **작업 이력** 또는 **작업 상태 새로고침**으로 결과를 확인합니다.

생성 버튼을 누른 뒤 연결이 끊기면 먼저 같은 작업의 상태를 확인하세요. 응답이 없다고 같은 작업을 반복 제출하거나 새 작업으로 다시 생성하지 않습니다.

## 작업 이력과 증빙

**작업 이력**에서 광고명, 작업 번호 또는 신규 광고 번호로 검색하고 상태로 좁힐 수 있습니다. **이전 작업 더 보기**로 이전 이력을 불러옵니다. 이력과 열린 상세의 진행 상태는 화면이 활성화되어 있고 업로드 중이 아닐 때 약 15초마다 갱신됩니다.

광고명을 눌러 상세를 열면 작업 번호, `rh-op:<작업 번호>` 검색 태그, 참조 광고, 신규 광고·creative 번호, 세 영상과 작업 기록을 볼 수 있습니다. **작업 증빙 다운로드**는 설정, 검수본, 소재 정보, 감사 기록과 외부 생성 요청 기록을 JSON으로 내보냅니다. **검색 태그 복사**는 Ads Manager에서 생성된 리소스를 찾을 때 사용합니다.

| 화면 상태 | 의미와 다음 행동 |
|---|---|
| 업로드 대기 | 초안이 있거나 일부 영상 업로드가 남았습니다. 같은 작업에서 업로드를 이어갑니다. |
| 제출 준비 | 세 영상 업로드가 완료됐습니다. 상세에서 검수하고 명시적으로 신규 PAUSED 생성을 제출합니다. |
| 제출됨 / CDN 검증 중 / Meta 영상 처리 중 / 광고 생성 중 | 서버가 처리 중입니다. 상태를 확인하며 기다립니다. |
| 마케터 검수 대기 | 작업대가 새 광고의 PAUSED 상태와 필요한 검증을 확인했습니다. Ads Manager에서 최종 검수합니다. Meta 심사 승인이나 광고 집행 완료를 뜻하지 않습니다. |
| 안전 중단 | 검증에 실패했습니다. **중단 전에 영상·creative·광고가 이미 생성됐을 수 있습니다.** 상세 오류와 작업 번호를 관리자에게 전달합니다. |
| 생성 여부 확인 필요 | Meta 생성 요청의 결과를 확정하지 못했습니다. 자동 재시도하지 않습니다. 같은 작업 상태와 검색 태그를 확인하고 관리자에게 넘깁니다. |

광고 번호가 비어 있어도 미생성이 확정된 것은 아닙니다. 관리자는 작업 원장과 Meta의 실제 상태를 함께 확인해야 합니다. **Owner 안전 재확인**은 owner 브라우저에만 표시되며, 기존 광고를 수정하거나 생성 POST를 다시 보내는 기능이 아닙니다. 확인에 필요한 기록이 부족하면 복구를 중단합니다.

`AD_PAUSED_TIMEOUT`은 새 광고가 생성됐지만 Meta의 최종 PAUSED 상태 확인이 제한 시간 안에 끝나지 않았다는 뜻입니다. 광고 설정이 PAUSED여도 Meta 심사가 진행 중이면 발생할 수 있습니다. 본인이 만든 작업이고 확정 광고·creative·최초 이력이 있으면 CLI의 `recheck-paused`로 한 번 재확인할 수 있습니다. 조건에 맞지 않거나 계속 심사 중이면 증빙을 남기고 관리자에게 전달합니다. 같은 작업을 새로 제출하지 않습니다.

## 업로드 중단·로그인 만료 복구

1. 로그인 만료 안내가 나오면 **다시 로그인**합니다.
2. 작업 이력에서 중단된 **업로드 대기** 작업을 열고 **업로드 이어가기**를 누릅니다.
3. 안내된 원본 파일 세 개를 다시 선택합니다. 파일명·크기·SHA-256과 광고 설정·검수 해시가 기존 작업과 같아야 합니다.
4. 참조 광고를 다시 확인하고 업로드를 이어갑니다. 완료된 파일은 다시 보내지 않으며, 확인된 업로드 조각은 같은 작업의 기록을 사용합니다.

파일을 다시 인코딩하거나 이름을 바꾼 경우 기존 작업을 이어갈 수 없습니다. **새 작업으로 전환**을 사용하되 기존 작업이 이미 제출됐거나 생성 결과가 불명확한 경우에는 먼저 관리자에게 확인합니다. 참조 검수본이 바뀌었거나 임시 파일 보관 기간이 끝난 작업도 재개할 수 없습니다.

이미 **제출 준비**라면 파일을 다시 올리지 말고 상세에서 검수합니다. **안전 중단**이나 **생성 여부 확인 필요**는 업로드 재개 대상이 아닙니다.

## Ads Manager 최종 검수와 소재 이력

**마케터 검수 대기** 작업의 **Ads Manager에서 검수**를 열어 다음을 확인합니다.

- 광고 번호와 creative 번호가 참조 광고의 번호와 다릅니다.
- 광고가 PAUSED이며 올바른 광고 세트에 있습니다.
- Feed, Story, Reels에 맞는 영상과 배치가 연결되어 있습니다.
- 본문·제목·CTA·앱 목적지가 검수한 참조 설정과 같습니다.
- Meta의 경고와 이슈를 확인했습니다.

활성화, 예산 결정과 기존 광고 중지는 담당자의 기존 Ads Manager 승인 절차로 수행합니다. 기존 광고의 이름이나 소재를 새 소재로 바꾸지 않습니다.

상세의 **소재 이력 확인**은 버튼을 누른 시점의 광고명·creative를 최초 생성 기록과 비교합니다. 변경이 감지되면 같은 광고 번호의 성과를 새 소재 성과로 단정하지 말고 관리자에게 변경 이력을 확인합니다. 상시 감시나 외부 Ads Manager 수정 차단 기능은 아닙니다.

이전 버전 작업에는 검수본이나 최초 생성 기준이 없을 수 있습니다. 이 경우 **기준 없음 / untracked**로 표시하며 현재 값을 과거 기준으로 만들어 넣지 않습니다.

## Windows와 Claude Code 연결

작업대의 **Claude Code 연결 → Windows 시작 ZIP 다운로드**가 기본 시작 경로입니다. ZIP에는 `rh-meta.mjs`, `CLAUDE.md`, `START_HERE_KO.md`, `start-windows.cmd`, manifest 예시가 들어 있습니다. 모두 압축 해제하고 `START_HERE_KO.md`를 읽습니다. 필요한 파일은 같은 화면에서 개별로 받을 수도 있습니다.

### 처음 한 번 연결

1. `start-windows.cmd`를 더블클릭합니다. Node.js 22 이상과 연결 상태를 진단합니다. Node.js가 없거나 오래됐으면 <https://nodejs.org/en/download>에서 직접 설치한 뒤 터미널을 다시 엽니다. 실행기는 자동 설치·관리자 권한 요청·ExecutionPolicy 변경을 하지 않습니다.
2. 작업대의 **개인 작업 토큰**에 기기 이름을 쓰고 **7일 토큰 발급**을 누릅니다. 창을 닫으면 토큰 원문을 다시 볼 수 없습니다.
3. 압축을 푼 폴더에서 본인이 직접 PowerShell을 열고 아래 명령을 실행합니다. `login`의 숨김 입력에만 토큰을 붙여넣습니다.

```powershell
.\start-windows.cmd login
.\start-windows.cmd doctor
.\start-windows.cmd whoami
```

`doctor`의 `ok: true`로 연결 상태를 확인하고, `whoami`로 본인 이메일을 확인합니다. `doctor` 결과는 JSON이며 정상은 종료 코드 0, 조치 필요는 1입니다. 로그인 없음, 권한 문제, 네트워크 실패, API 경로의 로그인 페이지 반환 등을 구분해 다음 행동을 알려줍니다. 만료·취소·잘못된 토큰은 서버 응답만으로 구분하지 못합니다.

토큰 원문과 `%USERPROFILE%\.rh-meta-workbench\credentials.json`을 Claude에게 보여주지 마세요. CLI가 저장된 로그인을 내부에서 사용합니다. 토큰을 채팅·명령 인수·manifest·Git에 넣지 않습니다. 웹에서 발급한 토큰은 7일 뒤 만료되므로 새로 발급해 직접 다시 로그인합니다. 서버가 허용하는 최대 기간은 30일입니다.

저장 토큰은 현재 Windows 사용자만 접근하도록 ACL을 검사하지만 암호화된 금고는 아닙니다. 로컬 NTFS 사용자 프로필이 필요합니다. 권한 검사를 우회하지 마세요. CLI가 Access 로그인 HTML이나 리다이렉트를 받으면 운영자에게 `/agent/v1/*` 전용 경로 설정을 확인해 달라고 합니다. 웹 전체 인증은 유지합니다.

### Claude에게 폴더와 작업 범위 전달

압축을 푼 폴더에서 Claude Code를 열고 화면의 **시작 프롬프트 복사** 또는 `START_HERE_KO.md`의 프롬프트를 사용합니다. 다음 정보를 실제 값으로 채우세요.

- 소재 폴더 경로: 한글·공백을 포함해도 됩니다.
- 대상 광고 세트와 검수한 참조 광고: ID 또는 정확한 이름을 씁니다.
- 신규 광고명과 언어, 검수한 세 영상.
- 승인 범위: 해당 참조 설정을 유지해 새 PAUSED 광고를 몇 개 생성할지 명시합니다. 생성 전 확인을 원하면 초안 업로드까지만 승인합니다.

사용자가 이미 대상·참조·설정 유지·신규 PAUSED 생성을 승인했다면 Claude는 같은 승인을 다시 묻지 않고 그 범위 안에서 진행합니다. 정보가 빠졌거나 후보가 여러 개이거나 검수본이 바뀐 경우에만 필요한 내용을 묶어 확인합니다. 이름만으로 실제 영상 화면비·게임·내용이 검증됐다고 판단하지 않습니다.

기존 초안이 있다면 작업 ID를 함께 전달하세요. Claude는 새 `prepare`를 반복하기 전에 같은 작업을 찾아 재개합니다. 이미지·playable·다른 게임은 현재 MP4 흐름으로 제출하지 않습니다.

### 자동 작업과 직접 확인 명령

Claude의 순서는 **폴더 확인 → doctor → 대상·참조 조회/preview → manifest 작성 → check-manifest → prepare 또는 resume → 승인된 submit 한 번 → wait → lineage → export**입니다.

아래 예시는 압축을 푼 폴더의 PowerShell 기준입니다. 경로는 따옴표로 감쌉니다. manifest의 상대 영상 경로는 manifest 폴더 기준이며, JSON의 역슬래시는 `\\`로 쓰거나 `/`를 사용합니다. `ADSET_ID`, `REFERENCE_AD_ID`, `OPERATION_UUID`는 실제 조회 결과로 대체합니다.

```powershell
.\start-windows.cmd doctor
.\start-windows.cmd adsets
.\start-windows.cmd ads --adset ADSET_ID
.\start-windows.cmd preview --adset ADSET_ID --ad REFERENCE_AD_ID
.\start-windows.cmd check-manifest "C:\광고 소재\이번 주\manifest.json"
.\start-windows.cmd prepare "C:\광고 소재\이번 주\manifest.json"
```

`check-manifest`는 인증이나 네트워크 없이 JSON/BOM, 세 화면비 항목, 원본 파일·MP4 헤더·크기·SHA-256을 확인합니다. 결과가 정상이어도 해상도·회전·재생·게임/내용·Meta 호환성·참조 변경까지 검증한 것은 아닙니다. `notChecked`를 확인하고 실제 영상과 preview를 검수합니다. `prepare`는 초안과 업로드만 만들며, 출력되는 작업 ID를 즉시 보관합니다.

승인된 범위의 신규 PAUSED 생성은 같은 작업 ID로 한 번만 제출합니다.

```powershell
.\start-windows.cmd submit OPERATION_UUID --confirm-new-paused
.\start-windows.cmd wait OPERATION_UUID --interval 10 --timeout 600
.\start-windows.cmd lineage OPERATION_UUID
.\start-windows.cmd export OPERATION_UUID --output ".\receipt-OPERATION_UUID.json"
```

`wait`는 조회만 하며 시간 초과가 작업 취소를 뜻하지 않습니다. `AWAITING_MARKETER_REVIEW`도 Meta 심사 승인이나 집행 완료를 뜻하지 않습니다. 실패·생성 여부 불명확 상태는 성공으로 보고하지 않고 같은 ID의 상태와 증빙을 확인합니다. `AD_PAUSED_TIMEOUT`이나 Meta 심사 대기는 새로 생성할 이유가 아닙니다.

### 기존 초안과 ID 복구

업로드 중 끊긴 미제출 초안은 같은 ID·manifest·원본 파일로 재개합니다. 완료된 소재를 다시 보내지 않습니다.

```powershell
.\start-windows.cmd status OPERATION_UUID
.\start-windows.cmd resume OPERATION_UUID --manifest ".\manifest.json"
.\start-windows.cmd list --query "신규 광고명" --limit 40
```

초안 생성 응답을 못 받아 ID가 없으면 이력에서 광고명·시각·담당자·참조·원본 hash를 대조합니다. `nextBefore`가 있으면 `--before UUID`로 다음 페이지를 읽습니다. 같은 작업인지 모호하면 확인하고, 찾기 전에 `prepare`를 반복하지 않습니다.

### 본인 작업의 PAUSED 상태 재확인

본인이 초안을 만든 작업(`submitted_by`)이 `FAILED_TERMINAL` + `AD_PAUSED_TIMEOUT`이면 다음을 한 번 실행할 수 있습니다. 확정된 광고·creative·최초 이력 기록이 있어야 합니다.

```powershell
.\start-windows.cmd recheck-paused OPERATION_UUID
```

서버는 기존 광고·creative·최초 이력과 현재 참조·검수 hash·광고 identity·엄격한 PAUSED 상태·미리보기를 모두 다시 확인합니다. Meta에는 조회 요청만 보내며, 모든 검증이 통과하면 기존 작업을 **마케터 검수 대기**로 갱신합니다. 새 광고·creative를 생성하거나 기존 광고를 수정하지 않습니다.

성공 응답 뒤에도 같은 ID의 `status`로 `AWAITING_MARKETER_REVIEW` 상태를 확인하고 `lineage`와 `export`를 마칩니다.

`AD_PAUSED_PENDING` 등으로 계속 심사 중이거나 검증에 실패하면 재확인을 반복하지 않습니다. 같은 작업의 `status`와 `export`로 상태·증빙을 남기고 관리자에게 전달한 뒤 멈춥니다. 성공을 주장하거나 `prepare`·`submit`을 다시 실행하지 않습니다.

생성 결과가 불명확하거나 확정 ID·최초 이력이 없거나 다른 오류이거나 다른 사람의 작업이면 개인 재확인 대상이 아닙니다. 기존 **Owner 안전 재확인**으로 전달합니다. 개인 토큰으로는 이 owner 기능, 토큰 발급·취소, 기존 광고 수정·활성화·예산 변경을 실행할 수 없습니다. 두 재확인 기능 모두 심사 완료를 강제하거나 광고를 다시 생성하지 않습니다.

### 토큰 취소와 파일 받기

작업대의 **Claude Code 연결**에서 해당 토큰을 취소하면 서버 접근이 중단됩니다. ` .\start-windows.cmd logout`은 로컬 사본만 삭제합니다. 분실·노출 시에는 작업대에서 취소하고 새로 발급합니다. Owner는 모든 개인 토큰을 관리할 수 있습니다.

` .\start-windows.cmd download OPERATION_UUID --ratio 9x16 --output ".\received.mp4"`로 인증된 영상을 받을 수 있습니다. 다운로드와 내보내기는 기존 출력 파일을 덮어쓰지 않습니다.

## 보관과 이용 한도

미제출 임시 업로드는 생성 후 2일이 지나면 정리 대상입니다. 성공한 작업의 임시 파일은 처리 후 정리하며, 그 외 제출된 작업의 임시 파일은 마지막 변경 후 7일이 지나면 정리 대상입니다. 정기 정리 시점에 따라 실제 삭제 시각은 달라질 수 있습니다.

Meta가 사용할 공개 `/meta/` 소재는 자동 삭제하지 않습니다. 공개 광고 영상은 비밀 저장소에 보관되는 파일이 아닙니다. 기존 공개 경로를 직접 덮어쓰거나 삭제하지 마세요.

사용자별 업로드 한도는 24시간 동안 20개 작업·5 GiB입니다. 이 한도는 Cloudflare 계정 전체의 청구 상한이 아닙니다. 작업대 권한이나 운영 Meta 토큰의 최소 권한 전환은 운영자가 관리합니다.
