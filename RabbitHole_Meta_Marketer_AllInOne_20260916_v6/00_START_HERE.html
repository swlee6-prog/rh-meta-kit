Claude Code 데스크톱에 소재 작업 맡기기

  1. 작업대의 Windows 시작 ZIP을 내려받아 모두 압축 해제합니다.
  2. Claude Code 데스크톱에서 압축을 푼 폴더를 엽니다. 일반 Claude 웹 채팅에 ZIP을 첨부하는 방식이 아닙니다.
  3. 소재 폴더와 원하는 작업을 말합니다. Claude가 동봉된 CLAUDE.md를 읽고 파일 검사부터 업로드·결과 확인까지 진행합니다.

이렇게 말하세요

이 폴더의 CLAUDE.md를 읽고 [소재 폴더 경로]의 영상으로 [참조 광고 이름] 설정을 그대로 유지해 [대상 광고 세트 이름]에 새 PAUSED 광고 1개를 만들어 주세요.
새 광고 이름은 [이름], 언어는 [영어]로 해 주세요.

예전에 정한 대상이나 참조는 다시 적지 않아도 됩니다. 기존 작업을 계속하려면 “하던 작업을 이어서 확인해 주세요”라고 말하세요. 생성 전에 확인하고 싶다면 “초안 업로드까지만 준비해 주세요”라고 말하면 됩니다. 명령·광고 번호·설정 JSON은 직접 입력하지 않습니다.

이어하기나 결과 확인은 Claude가 기존 이력부터 찾습니다. 이미 완료됐거나 제출 후 진행 중이면 원본 폴더를 다시 요구하거나 같은 광고를 새로 만들지 않습니다. 업로드가 남았고 원본 위치를 찾을 수 없을 때만 폴더를 확인합니다. 설정 파일과 증빙은 작업별로 보관하므로 이전 파일을 직접 수정하거나 삭제할 필요가 없습니다.

연결은 필요할 때만

이미 연결된 PC면 저장된 인증으로 바로 진행합니다. 처음이거나 만료·취소됐을 때만 Claude가 브라우저 연결을 시작합니다. 열린 작업대에 회사 계정으로 로그인하고 Claude에 표시된 코드와 같은지 확인한 다음 이 기기 연결에 동의를 누르세요. 코드가 자동 입력돼도 자동 승인되지는 않습니다. 본인이 시작하지 않은 요청은 승인하지 않습니다.

Claude가 연결 완료를 확인하므로 토큰을 복사할 필요는 없습니다. 코드는 10분 안에 승인·수령하며 한 번만 사용합니다. 연결은 완료 후 7일 유효하고, 작업대의 연결 및 개인 토큰에서 취소할 수 있습니다. 만료됐으면 Claude에게 다시 연결해 달라고 말하세요.

준비할 것과 결과 확인

  • PC에 Node.js 22 이상과 로컬 파일·터미널을 사용할 수 있는 Claude Code가 필요합니다. Node.js가 없으면 https://nodejs.org/en/download에서 설치하고 Claude Code를 다시 여세요. 자동 설치나 관리자 권한 요청은 없습니다.
  • 소재는 이 PC에서 접근할 수 있는 폴더에 둡니다. 현재 등록된 게임(Rabbit Hole·Card of Demon Slayer)의 9:16·1:1·16:9 MP4 한 묶음, 파일당 최대 512 MiB를 지원합니다. 이미지·playable·미등록 게임은 지원하지 않습니다.
  • Claude는 지정한 폴더 안에서 실제 영상 크기와 회전을 확인합니다. 영상이 빠졌으면 다른 폴더의 비슷한 파일로 채우지 않고 필요한 원본 경로만 한 번에 묻습니다. 후보가 여러 개이거나 게임·영상 내용이 불명확하면 필요한 구분만 묻습니다. CDN 주소를 추측해 원본을 찾지 않습니다.
  • Claude는 이름 확인 명령으로 전체 목록에서 대상과 참조가 각각 하나인지 확인합니다. 같은 이름이 여러 개면 설정이 같아도 첫 후보를 고르지 않고 캠페인·상태 등 구분할 정보만 한 번에 묻습니다. 광고 번호 입력은 요구하지 않으며 목록 조회가 끝나지 않으면 임의로 선택하지 않습니다.
  • 이미 승인한 설정을 유지하는 작업에는 같은 승인을 다시 묻지 않습니다. 참조가 바뀌었으면 Claude가 작업 상태와 기존 생성 기록을 확인하고 차이를 짧게 설명합니다. 변경 설정을 사용하려면 새 검수와 새 초안이 필요할 수 있으며, 기존 업로드를 그대로 재개할 수 있다고 미리 약속하거나 참조 광고를 대신 되돌리지 않습니다.
  • 마케터 검수 대기는 Meta 심사 승인이나 집행 시작을 뜻하지 않습니다. 최종 집행은 Ads Manager에서 검수한 뒤 결정합니다. 중단되거나 심사 중이면 같은 광고를 다시 만들지 않고 기존 작업을 확인합니다.

결과는 상태·소재 결과·증빙·필요한 다음 행동을 3~5줄로 안내합니다. 오류가 나도 원인과 필요한 확인만 짧게 묻습니다. 테스트 환경에서 확인한 결과는 실제 광고 생성과 구분해 알려드립니다.

브라우저 연결이 어려울 때만 작업대의 접힌 토큰을 직접 입력해 연결하기 안내를 사용합니다. 토큰은 사람이 직접 연 CLI login의 숨김 입력에만 넣고 Claude 채팅이나 파일로 전달하지 않습니다. Windows 인증 저장에는 로컬 NTFS 사용자 프로필이 필요하며 권한 오류는 관리자에게 문의하세요. 자세한 안전·복구 절차는 Claude가 CLAUDE.md에서 읽습니다.

Rabbit Hole 소재 작업대 — 마케터 가이드

작업대: https://meta-ads.rabbithole-studios.io/

새 영상은 새 creative와 새 광고 번호로 생성하고, 광고는 PAUSED로 준비합니다. 기존 광고의 이름·소재·예산을 바꾸거나 광고를 활성화하는 기능은 제공하지 않습니다. 같은 광고 번호에 새 소재를 덮어쓰면 과거 성과와 새 소재 성과가 섞일 수 있습니다.

이 문서는 새 작업대 화면과 CLI의 사용법입니다. 이 문서의 메뉴가 없거나 CLI가 로그인 페이지를 반환하면 운영자에게 배포·경로 설정 상태를 확인합니다.

주소와 파일 찾기 — 예전 CDN 안내보다 이 절차를 우선합니다

  • 사람이 여는 작업대: https://meta-ads.rabbithole-studios.io/
  • CLI 연결: 위 작업대의 /agent/v1/*. rh-meta.mjs에 주소가 고정되어 있으므로 CDN 주소로 바꾸지 않습니다.
  • 영상 전송용 CDN: https://creative-cdn.rabbithole-studios.io/meta/.... 업로드·제출 후 서버가 결정하는 영상 주소입니다. 로그인 페이지나 소재 검색 서비스가 아닙니다.

신규 소재는 CDN에서 먼저 찾지 않습니다. 마케터가 지정한 로컬·접근 가능한 NAS 폴더의 MP4 3개를 check-manifest → prepare(기존 미제출 초안은 resume)로 올리고, 승인된 submit 후 서버가 공개 경로와 Meta 영상 ID를 처리하게 합니다. 공개 경로에는 정규화된 광고명·화면비·파일 해시가 들어가므로 광고명에 크기나 확장자를 붙여 추측한 URL은 정확한 주소가 아닐 수 있습니다.

기존 작업은 CLI list·status·export로 찾아 기록된 실제 public_key 또는 URL만 사용합니다. CDN 루트의 403, 임의의 몇 경로에서 나온 403/404만으로 도메인 전체 차단·원본 파일 없음·업로드 불가를 결론 내리지 않습니다. Range 요청의 206도 정상 응답입니다. 도메인이 연결된다는 것만으로 특정 파일이 올라갔다고 볼 수도 없습니다.

기존 작업의 이어하기·결과 확인은 원본 폴더를 다시 묻기 전에 이력부터 찾습니다. 상태와 기존 증빙만으로 확인할 수 있으면 그대로 마무리하고, 실제 업로드가 남았을 때만 원본 위치를 확인합니다. 이름이 비슷하다는 이유로 다른 영상을 고르거나 새 작업을 반복 생성하지 않습니다. 오래된 ‘CDN URL 조합 → Meta MCP’ 지침이 남아 있으면 이 패키지의 CLI 절차로 전환합니다.

이 방식은 로컬 파일과 터미널을 사용할 수 있는 Claude Code용입니다. 일반 Claude 웹 채팅·클라우드 예약 루틴에 ZIP을 첨부하는 것만으로 로컬 CLI가 실행되지는 않습니다. 그런 환경에서는 작업대 브라우저로 직접 업로드하거나 Claude Code에서 이 폴더를 여세요.

Claude Code 데스크톱으로 시작하는 세 단계

  1. Claude Code 연결 화면에서 Windows 시작 ZIP을 내려받아 모두 압축 해제합니다.
  2. Claude Code 데스크톱에서 압축을 푼 폴더를 엽니다. 로컬 파일과 터미널을 사용할 수 있는 환경이어야 합니다.
  3. 소재 폴더 경로와 원하는 작업을 말합니다. 예를 들어 “이번 주 영상 폴더로 영어 광고 세트에 기존 참조 광고의 문구를 유지해 새 PAUSED 광고 하나를 만들어 주세요”라고 요청합니다. Claude가 필요한 이름을 조회하고 파일 검사부터 결과 확인까지 처리합니다.

이미 연결된 PC면 저장된 인증으로 바로 진행합니다. 처음 연결하거나 만료됐을 때만 열린 브라우저에서 회사 계정으로 로그인하고 같은 코드를 확인해 이 기기 연결에 동의합니다. 토큰을 복사하거나 명령·광고 번호·설정 JSON을 직접 입력할 필요가 없습니다. Node.js 22 이상은 PC에 설치돼 있어야 합니다.

시작 전 확인

  • 대상은 등록된 게임의 광고계정입니다(Rabbit Hole 2810899719287325, Card of Demon Slayer 1080208264434418). 조회 명령에는 --game, manifest에는 gameId로 지정합니다. 이미지·playable·미등록 게임은 이 흐름에서 지원하지 않습니다.
  • 9:16, 1:1, 16:9 MP4를 하나씩 준비합니다. 파일당 최대 512 MiB이며, 브라우저에서 영상과 화면비를 확인할 수 있어야 합니다.

브라우저에서 새 광고 준비

1. 광고 세트와 참조 광고 검수

  1. 새 광고 준비를 엽니다.
  2. 대상 광고 세트를 선택하고, 그 세트의 참조 광고를 선택합니다. 목록이 길면 더 불러오기를 사용합니다. 목록 조회가 실패하면 목록 다시 불러오기를 누릅니다.
  3. 정확한 ID를 알고 있다면 광고 ID로 직접 선택을 펼쳐 입력할 수 있습니다. 직접 입력해도 계정·광고 세트 검증은 동일하게 적용됩니다.
  4. 참조 광고 확인을 누릅니다. 광고명, 캠페인, 광고 세트, 본문, 제목, CTA와 목적지를 읽고 문구·CTA·목적지를 확인했습니다.에 체크합니다.

참조 광고 선택이나 ID를 바꾸면 다시 검수해야 합니다. 검수한 뒤 참조 광고의 이름·소재·문구 등이 바뀌면 서버가 생성을 중단합니다. 변경 내용을 확인하고 최신 검수본으로 새 작업을 준비하세요.

2. 세 영상 업로드

  1. 기존 광고와 구분되는 신규 광고명과 언어를 입력합니다. 광고명은 160자 이하이며 문자·숫자·공백과 _ . ( ) -를 사용할 수 있습니다.
  2. 세 화면비에 맞는 MP4를 선택합니다. 각 영상의 재생, 해상도, 길이와 내용을 확인합니다.
  3. 업로드하고 검수하기를 누릅니다. 파일 해시 계산과 업로드가 끝날 때까지 창을 유지합니다.
  4. 업로드가 끝나면 상세가 열리고 상태가 제출 준비가 됩니다. 이 단계에서는 Meta 광고를 아직 생성하지 않습니다.

3. 신규 PAUSED 생성 확인

  1. 상세 화면에서 업로드된 세 영상을 다시 확인합니다. 필요하면 영상 다운로드로 원본을 받습니다.
  2. 세 영상을 확인했습니다. 기존 광고를 변경하지 않고 새 PAUSED 광고를 생성합니다.에 체크합니다.
  3. 새 PAUSED 광고 생성을 한 번 누릅니다.
  4. 제출이 확인되면 서버가 처리를 계속하므로 브라우저를 닫아도 됩니다. 작업 이력 또는 작업 상태 새로고침으로 결과를 확인합니다.

생성 버튼을 누른 뒤 연결이 끊기면 먼저 같은 작업의 상태를 확인하세요. 응답이 없다고 같은 작업을 반복 제출하거나 새 작업으로 다시 생성하지 않습니다.

작업 이력과 증빙

작업 이력에서 광고명, 작업 번호 또는 신규 광고 번호로 검색하고 상태로 좁힐 수 있습니다. 이전 작업 더 보기로 이전 이력을 불러옵니다. 이력과 열린 상세의 진행 상태는 화면이 활성화되어 있고 업로드 중이 아닐 때 약 15초마다 갱신됩니다.

광고명을 눌러 상세를 열면 작업 번호, rh-op:<작업 번호> 검색 태그, 참조 광고, 신규 광고·creative 번호, 세 영상과 작업 기록을 볼 수 있습니다. 작업 증빙 다운로드는 설정, 검수본, 소재 정보, 감사 기록과 외부 생성 요청 기록을 JSON으로 내보냅니다. 검색 태그 복사는 Ads Manager에서 생성된 리소스를 찾을 때 사용합니다.

업로드 대기 초안이 있거나 일부 영상 업로드가 남았습니다. 같은 작업에서 업로드를 이어갑니다.
제출 준비 세 영상 업로드가 완료됐습니다. 상세에서 검수하고 명시적으로 신규 PAUSED 생성을 제출합니다.
제출됨 / CDN 검증 중 / Meta 영상 처리 중 / 광고 생성 중 서버가 처리 중입니다. 상태를 확인하며 기다립니다.
마케터 검수 대기 작업대가 새 광고의 PAUSED 상태와 필요한 검증을 확인했습니다. Ads Manager에서 최종 검수합니다. Meta 심사 승인이나 광고 집행 완료를 뜻하지 않습니다.
안전 중단 검증에 실패했습니다. 중단 전에 영상·creative·광고가 이미 생성됐을 수 있습니다. 상세 오류와 작업 번호를 관리자에게 전달합니다.
생성 여부 확인 필요 Meta 생성 요청의 결과를 확정하지 못했습니다. 자동 재시도하지 않습니다. 같은 작업 상태와 검색 태그를 확인하고 관리자에게 넘깁니다.

광고 번호가 비어 있어도 미생성이 확정된 것은 아닙니다. 관리자는 작업 원장과 Meta의 실제 상태를 함께 확인해야 합니다. Owner 안전 재확인은 owner 브라우저에만 표시되며, 기존 광고를 수정하거나 생성 POST를 다시 보내는 기능이 아닙니다. 확인에 필요한 기록이 부족하면 복구를 중단합니다.

AD_PAUSED_TIMEOUT은 새 광고가 생성됐지만 Meta의 최종 PAUSED 상태 확인이 제한 시간 안에 끝나지 않았다는 뜻입니다. 광고 설정이 PAUSED여도 Meta 심사가 진행 중이면 발생할 수 있습니다. 본인이 만든 작업이고 확정 광고·creative·최초 이력이 있으면 CLI의 recheck-paused로 한 번 재확인할 수 있습니다. 조건에 맞지 않거나 계속 심사 중이면 증빙을 남기고 관리자에게 전달합니다. 같은 작업을 새로 제출하지 않습니다.

업로드 중단·로그인 만료 복구

  1. 로그인 만료 안내가 나오면 다시 로그인합니다.
  2. 작업 이력에서 중단된 업로드 대기 작업을 열고 업로드 이어가기를 누릅니다.
  3. 안내된 원본 파일 세 개를 다시 선택합니다. 파일명·크기·SHA-256과 광고 설정·검수 해시가 기존 작업과 같아야 합니다.
  4. 참조 광고를 다시 확인하고 업로드를 이어갑니다. 완료된 파일은 다시 보내지 않으며, 확인된 업로드 조각은 같은 작업의 기록을 사용합니다.

파일을 다시 인코딩하거나 이름을 바꾼 경우 기존 작업을 이어갈 수 없습니다. 새 작업으로 전환을 사용하되 기존 작업이 이미 제출됐거나 생성 결과가 불명확한 경우에는 먼저 관리자에게 확인합니다. 참조 검수본이 바뀌었거나 임시 파일 보관 기간이 끝난 작업도 재개할 수 없습니다.

이미 제출 준비라면 파일을 다시 올리지 말고 상세에서 검수합니다. 안전 중단이나 생성 여부 확인 필요는 업로드 재개 대상이 아닙니다.

Ads Manager 최종 검수와 소재 이력

마케터 검수 대기 작업의 Ads Manager에서 검수를 열어 다음을 확인합니다.

  • 광고 번호와 creative 번호가 참조 광고의 번호와 다릅니다.
  • 광고가 PAUSED이며 올바른 광고 세트에 있습니다.
  • Feed, Story, Reels에 맞는 영상과 배치가 연결되어 있습니다.
  • 본문·제목·CTA·앱 목적지가 검수한 참조 설정과 같습니다.
  • Meta의 경고와 이슈를 확인했습니다.

활성화, 예산 결정과 기존 광고 중지는 담당자의 기존 Ads Manager 승인 절차로 수행합니다. 기존 광고의 이름이나 소재를 새 소재로 바꾸지 않습니다.

상세의 소재 이력 확인은 버튼을 누른 시점의 광고명·creative를 최초 생성 기록과 비교합니다. 변경이 감지되면 같은 광고 번호의 성과를 새 소재 성과로 단정하지 말고 관리자에게 변경 이력을 확인합니다. 상시 감시나 외부 Ads Manager 수정 차단 기능은 아닙니다.

이전 버전 작업에는 검수본이나 최초 생성 기준이 없을 수 있습니다. 이 경우 기준 없음 / untracked로 표시하며 현재 값을 과거 기준으로 만들어 넣지 않습니다.

Windows와 Claude Code 연결

Windows 시작 ZIP 다운로드가 기본 경로입니다. 모두 압축 해제하고 Claude Code 데스크톱에서 해당 폴더를 엽니다. 동봉된 CLAUDE.md가 Claude의 작업 지침이며 START_HERE_KO.md에 복사할 예시가 있습니다. 일반 Claude 웹 채팅에 ZIP을 첨부하는 것만으로 PC의 소재 폴더를 사용할 수는 없습니다.

폴더와 원하는 작업만 전달

원본 폴더 경로, 대상 광고 세트와 참조 광고의 이름, 원하는 광고 이름과 언어를 자연어로 말하세요. 이미 대화에서 정한 내용은 다시 입력하지 않아도 됩니다. Claude가 이름 조회 기능으로 전체 목록을 확인하고 후보가 하나일 때만 광고 번호와 검수 내용을 사용합니다. 동명 후보가 있으면 설정이 같아도 첫 광고를 고르지 않고, 캠페인 등 구분할 정보만 묻습니다. 설정 파일과 증빙도 Claude가 작업별로 직접 작성하며, 기존 파일이 있어도 삭제를 요청하지 않고 다른 이름으로 보관합니다. 원본이 빠졌으면 지정 폴더 밖의 비슷한 영상으로 채우지 않습니다.

같은 화면비 영상이 여러 개이거나 대상·참조 후보가 모호하거나 검수본이 바뀐 경우에만 필요한 구분을 묻습니다. 신규 PAUSED 생성 범위가 이미 승인됐으면 같은 승인을 반복 요청하지 않습니다. 생성 전에 확인하고 싶다면 “초안 업로드까지만 준비해 주세요”라고 말하세요.

Claude는 실제 MP4 크기와 회전을 읽어 세 화면비를 검사합니다. 파일명만으로 판단하지 않습니다. 폴더 탐색에는 제한이 있으므로 검수할 소재 묶음의 폴더를 지정하세요. 게임·영상 내용, 재생과 광고 설정은 검사 결과와 기존 검수 근거를 함께 확인합니다. 이미지·playable·다른 게임은 현재 MP4 흐름에 섞지 않습니다.

원본은 이 PC가 접근할 수 있는 로컬·NAS 폴더에서 가져옵니다. CDN 주소를 조합해 원본을 찾지 않습니다. 기존 결과는 작업 이력에 기록된 실제 경로만 사용하며, 일부 추측 URL의 응답만으로 도메인 전체 차단이나 파일 없음을 판단하지 않습니다.

이미 연결돼 있으면 바로 작업

Claude가 먼저 연결 상태를 진단합니다. 유효한 저장 인증이 있으면 그대로 작업하며 새 코드를 승인할 필요가 없습니다. 연결 명령도 기존 로그인을 재사용합니다.

처음 연결하거나 만료·취소된 경우에만 브라우저가 열립니다. 회사 계정으로 로그인하고 Claude에 표시된 코드와 브라우저 코드가 같은지 확인한 뒤 이 기기 연결에 동의를 누릅니다. 자동 입력은 승인과 다릅니다. 본인이 시작하지 않은 요청은 승인하지 마세요. Claude가 연결 완료까지 확인합니다.

연결 코드는 10분 안에 승인·수령하며 한 번만 사용합니다. 실제 연결은 완료 후 7일 유효합니다. 연결 화면의 승인은 완료 확인 전 단계이므로 PC에서 수령이 끝났는지는 Claude가 확인합니다. 코드가 만료됐거나 이미 사용됐다면 Claude에 연결을 다시 시작해 달라고 말하세요.

작업대의 연결 및 개인 토큰 목록에서 접근을 취소할 수 있습니다. 저장된 인증 원문을 열거나 Claude에게 전달하지 않습니다. 암호화된 금고는 아니며 Windows에서는 로컬 NTFS 사용자 프로필과 본인 접근 권한을 검사합니다. 권한 오류를 우회하지 말고 관리자에게 문의하세요.

Claude가 작업을 끝내는 순서

Claude는 연결 진단 → 소재 폴더 검사 → 기존 작업 검색 → 대상·참조 조회 및 검수 → 설정 작성 → 로컬 파일 검사 → 초안 준비 또는 재개 → 승인 범위의 한 번 생성 → 상태·소재 이력·증빙 확인을 수행합니다. 사용자는 명령이나 광고 번호를 대신 입력하지 않습니다.

원본과 검수 설정이 같은 미제출 초안은 재개합니다. 응답이 끊기거나 작업 ID를 즉시 받지 못해도 Claude가 이름·시각·담당자·참조·파일 기록으로 기존 작업을 먼저 찾습니다. 모호하면 구분만 확인하며, 찾기 전에 새 초안을 반복 생성하지 않습니다.

조회 시간 초과는 작업 취소가 아닙니다. 실패·생성 여부 불명확 상태도 성공으로 보고하지 않습니다. 실제 상태와 증빙을 확인하고 마케터가 이해할 수 있는 결과와 다음 행동을 안내합니다. 마케터 검수 대기는 Meta 심사 승인이나 집행 완료를 뜻하지 않습니다.

본인 작업의 PAUSED 상태 재확인

본인이 초안을 만든 작업이 최종 PAUSED 확인 시간 초과로 중단됐고 확정 광고·creative·최초 이력 기록이 있으면 Claude가 안전 재확인을 한 번 실행할 수 있습니다. 기존 광고·참조·검수 hash·최초 이력·정확한 PAUSED 상태·미리보기를 모두 다시 확인합니다. Meta에는 조회만 하고, 전부 통과하면 기존 작업을 마케터 검수 대기로 갱신합니다.

계속 심사 중이거나 검증에 실패하면 반복 실행하지 않습니다. 같은 작업의 상태·증빙을 남기고 관리자에게 전달한 뒤 멈춥니다. 새 광고를 만들거나 기존 작업을 재제출하지 않습니다. 생성 결과가 불명확하거나 확정 기록이 없거나 다른 오류·다른 사람의 작업이면 기존 Owner 안전 재확인 대상입니다. 두 재확인 기능 모두 심사 완료를 강제하거나 광고를 다시 생성하지 않습니다.

수동 연결이 필요한 경우

브라우저 연결을 사용할 수 없을 때만 접힌 토큰을 직접 입력해 연결하기 안내를 사용합니다. 이 경우 본인이 7일 토큰을 발급하고 직접 연 PowerShell에서 CLI login의 숨김 입력에 붙여넣습니다. Claude는 토큰을 대신 받거나 입력하지 않습니다. 토큰을 채팅·명령 인수·설정 파일·Git에 넣지 않습니다.

수동 진단이 필요하면 doctor는 연결 상태를, whoami는 이메일을 확인합니다. logout은 로컬 사본만 삭제하며 서버 접근 해지는 작업대에서 취소해야 합니다. 개인 연결로는 owner 기능, 토큰 발급·취소, 기존 광고 수정·활성화·예산 변경을 실행할 수 없습니다.

보관과 이용 한도

미제출 임시 업로드는 생성 후 2일이 지나면 정리 대상입니다. 성공한 작업의 임시 파일은 처리 후 정리하며, 그 외 제출된 작업의 임시 파일은 마지막 변경 후 7일이 지나면 정리 대상입니다. 정기 정리 시점에 따라 실제 삭제 시각은 달라질 수 있습니다.

Meta가 사용할 공개 /meta/ 소재는 자동 삭제하지 않습니다. 공개 광고 영상은 비밀 저장소에 보관되는 파일이 아닙니다. 기존 공개 경로를 직접 덮어쓰거나 삭제하지 마세요.

사용자별 업로드 한도는 24시간 동안 20개 작업·5 GiB입니다. 이 한도는 Cloudflare 계정 전체의 청구 상한이 아닙니다. 작업대 권한이나 운영 Meta 토큰의 최소 권한 전환은 운영자가 관리합니다.
